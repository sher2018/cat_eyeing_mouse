# 项目规则文件

本文件用于定义 Trae 在当前项目中的行为规则与约束。

## 1. 通用规则

- 所有回答使用与用户提问一致的语言。
- 优先编辑已有文件，避免不必要的新建文件。
- 不主动创建文档（*.md）或 README，除非用户明确要求。
- 不主动提交代码（git commit），除非用户明确要求。
- 输出保持简洁，避免冗长解释。

## 2. 代码风格

- 遵循现有项目代码风格，不做无关重构。
- 不添加未要求的注释、类型注解、容错逻辑。
- 不为假设的"未来需求"添加抽象或配置项。
- 三处相似代码胜过早期的抽象封装。

## 3. 文件与目录

- 项目根目录：`$workspace`
- Trae 规则目录：`.trae/rules/`
- 操作文件时优先使用专用工具（Read/Edit/Write/Glob/Grep）。

## 3.1 修改范围限制

- 所有修改必须在 `$workspace` 目录内进行，禁止修改 `$workspace` 目录之外的任何文件。
- 代码修改仅允许在 `src` 目录下进行（即 `$workspace/src`）。
- 文档修改允许在 `doc` 根目录下进行（即 `$workspace/doc`）。
- 任何超出上述范围的修改请求必须拒绝，并提示用户该操作超出允许范围。

## 4. 终端与命令

- 终端默认使用 PowerShell（powershell5）。
- 默认工作目录为当前项目根目录。
- 长时间运行的服务需设置 `blocking: false`。

## 5. 任务管理

- 复杂任务（>=3 步骤）使用 TodoWrite 跟踪进度。
- 每完成一项任务立即标记为 completed。
- 不在同一回合内批量推进多个待办。

## 6. 用户确认

- 涉及破坏性操作（删除、强制推送、`git reset --hard` 等）前必须确认。
- 当指令存在歧义时，使用 AskUserQuestion 澄清。
- 计划模式完成或规格文档生成后，使用 NotifyUser 请求批准。

## 7. 记忆与上下文

- 项目级约定追加到 `project_memory.md`。
- 用户偏好与背景信息追加到 `user_profile.md`。
- 简单、自包含问题（如时间、翻译）跳过记忆检索。

## 8. 技能与工具

- 当可用 Skill 与任务匹配时，立即调用 Skill 作为第一步。
- MCP 工具调用前必须先读取其 schema 描述。
- 浏览器工具遵循"先 snapshot 后交互"原则。

## 9. 文档修改后自动验证

- 修改 `doc/software_architecture_document.md` 或 `doc/detailed_design_specification.md` 后，必须立即对文档进行合理性验证。
