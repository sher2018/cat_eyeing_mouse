## 2. 业务目标与用户画像 (Business Goals & Personas)

### 2.1 业务目标
提供一个轻量、低侵入、零配置、纯前端的“桌面宠物式”浏览器陪伴插件。一只猫咪悬浮在网页右下角，眼睛/姿态随用户鼠标在屏幕上的位置实时切换 8 个朝向，营造出“猫始终盯着老鼠（鼠标）”的趣味效果，提升长时间浏览/办公场景的情绪体验。

* 可量化目标：
  * 安装即用，零配置项即可工作。
  * 状态切换感知延迟 ≤ 50ms（从鼠标移动到姿态切换视觉反馈）。
  * 恶意干扰当前网页 DOM 与样式的风险为 0（完全隔离的注入层）。
  * 同时上架 Google Chrome Web Store 与 Microsoft Edge Add-ons。

### 2.2 目标用户画像 (User Personas)

| Persona | 特征 | 核心诉求 |
|---------|------|----------|
| 知识工作者 / 研究员 | 长时间在浏览器中阅读、检索 | 缓解单调感，希望有一个不喧宾夺主的小陪伴 |
| 学生 / 内容创作者 | 注重个性化、趣味性 | 想要可爱、可拖动的桌面宠物，能随处摆放 |
| 开发者 / 技术爱好者 | 关注实现质量与隐私 | 要求纯前端、无网络请求、无数据上报、轻量 |

## 3. 功能性需求列表 (Functional Requirements)

> 编号规则：`FR-0XX`。优先级：`P0`（必须）/ `P1`（应该）/ `P2`（可选）。

### FR-001: P0 — 悬浮容器与默认停靠
* **需求描述：** 插件以独立悬浮层注入当前页面，默认悬浮于浏览器视口右下角、贴边、背景完全透明，不遮挡、不捕获页面默认交互。
* **验收标准 (Acceptance Criteria):**
  * AC1：安装后刷新任意页面，悬浮猫在视口右下角可见，与视口右/下边缘距离 ≤ 8px。
  * AC2：容器 `background: transparent`，无可见边框/阴影残留；不影响页面滚动条与页面布局（不得触发页面 reflow）。
  * AC3：容器 `pointer-events` 策略可配置：默认对页面事件“透传”，仅猫图像区域响应指针事件。

### FR-002: P0 — 可拖拽停靠
* **需求描述：** 用户可按住猫咪将其拖动并停靠到视口任意位置，松手后保持位置；刷新页面/重开标签页后位置持久化。
* **验收标准 (Acceptance Criteria):**
  * AC1：鼠标按下并移动时，猫咪跟随指针平滑移动，无肉眼可见抖动。
  * AC2：拖动过程中不选中文本、不触发页面链接、不引发页面滚动。
  * AC3：松手后坐标写入 `chrome.storage.local`，下次加载恢复。
  * AC4：当窗口尺寸变化导致记忆坐标越界时，自动回收至最近的有效视口内边缘。

### FR-003: P0 — 八方向 + 中心态姿态切换（核心）
* **需求描述：** 根据鼠标指针相对猫咪中心的位置，将平面划分为 **8 个 45° 方向扇区 + 1 个中心态**，加载 `res/move/` 目录下对应帧图片。
* **素材映射（契约，禁止硬编码歧义）:**

| 编号 | 文件 | 触发条件（鼠标相对猫咪中心位置） |
|------|------|----------------------------------|
| 中心 | `res/move/0.png` | 鼠标悬停在猫咪可交互区域内（hover） |
| 右上 | `res/move/1.png` | 指针位于右上扇区（约 -67.5° ~ -22.5°） |
| 右 | `res/move/2.png` | 指针位于右扇区（约 -22.5° ~ 22.5°） |
| 右下 | `res/move/3.png` | 指针位于右下扇区（约 22.5° ~ 67.5°） |
| 下 | `res/move/4.png` | 指针位于下扇区（约 67.5° ~ 112.5°） |
| 左下 | `res/move/5.png` | 指针位于左下扇区（约 112.5° ~ 157.5°） |
| 左 | `res/move/6.png` | 指针位于左扇区（约 157.5° ~ 180° 或 -180° ~ -157.5°） |
| 左上 | `res/move/7.png` | 指针位于左上扇区（约 -157.5° ~ -112.5°） |
| 上 | `res/move/8.png` | 指针位于上扇区（约 -112.5° ~ -67.5°） |

  > 角度坐标系：屏幕坐标，X 向右为正、Y 向下为正；`atan2(dy, dx)` 输出按上述区间归类。

* **验收标准 (Acceptance Criteria):**
  * AC1：鼠标移动到任一扇区中心点时，1 帧周期内（≤ 50ms）显示对应编号图片。
  * AC2：扇区边界（每 45° 的 ±22.5° 处）分类无歧义，边界点归属遵循“右开左闭”统一约定。
  * AC3：鼠标进入猫咪区域（hover）时立即切换为 `0.png`；离开后切回对应方向帧。
  * AC4：同一方向内连续移动不重复触发切换动画（防抖）。

### FR-004: P0 — 姿态过渡动画（Canvas 平滑过渡）
* **需求描述：** 姿态切换不得“硬切”，必须基于 `Canvas` 实现过渡。优先方案：**预生成过渡帧序列 + 序列帧播放**（项目已有 `gen_transition_frames.js` + `sharp` 依赖支撑）；备选方案：Canvas 帧间 `crossfade`（交叉淡入淡出）。
* **验收标准 (Acceptance Criteria):**
  * AC1：任意两个方向之间切换时，存在至少 1 个过渡阶段（如中间帧序列或 80~160ms 淡入淡出），无突兀跳变。
  * AC2：连续快速移动（鼠标快速画圈）时，过渡逻辑具备“抢占/合并”策略，避免动画堆栈卡顿。
  * AC3：过渡渲染使用独立 `requestAnimationFrame` 循环，离开页面（`visibilitychange` 隐藏）时暂停，节省 CPU。
  * AC4：Canvas 尺寸自适应高分屏（`devicePixelRatio` 缩放），不出现模糊。

### FR-005: P0 — 国际化 i18n 双语架构
* **需求描述：** 所有面向用户的文案（如右键菜单、Popup 提示、拖拽 tooltip）禁止硬编码，必须基于 WebExtension i18n 规范，语言包存放于 `/src/_locales/{lang}/messages.json`。
* **验收标准 (Acceptance Criteria):**
  * AC1：提供 `src/_locales/zh_CN/messages.json`（中文）与 `src/_locales/en/messages.json`（英文，默认回退）。
  * AC2：运行时通过 `chrome.i18n.getMessage(key)` 读取文案；UI 首选语言依据 `chrome.i18n.getUILanguage()`。
  * AC3：切换浏览器语言后，刷新页面文案随之切换，无遗留硬编码字符串。
  * AC4：所有 message key 采用 `snake_case` 命名并带 `description` 字段，便于翻译协作。

### FR-006: P0 — UI 静态资源路径解耦（/res 规范）
* **需求描述：** 全部静态资源（猫咪姿态图、过渡帧、应用图标、休息态图）统一存放于 `/res` 目录，按用途分子目录。
* **目录契约:**
  * `res/move/`：8 方向 + 中心姿态帧（`0.png` ~ `8.png`）。
  * `res/move/transitions/`（生成产物）：方向间的过渡帧序列（由 `gen_transition_frames.js` 产出）。
  * `res/rest/sit_back/`：休息态素材（如 `sit_back.png`）。
  * `res/icons/`：扩展图标 `icon16.png` / `icon48.png` / `icon128.png`。
* **验收标准 (Acceptance Criteria):**
  * AC1：代码中不得出现绝对磁盘路径或跨域 URL 引用素材，必须使用 WebExtension 相对资源路径（如 `chrome.runtime.getURL('res/move/1.png')`）。
  * AC2：素材加载失败时具备回退策略（如显示上一有效帧或透明占位），不抛出未捕获异常。

### FR-007: P0 — Chrome & Edge (Bing) 跨浏览器适配
* **需求描述：** 插件须同时无缝运行于 Google Chrome 与 Microsoft Edge (Bing)。
* **验收标准 (Acceptance Criteria):**
  * AC1：`manifest.json` 严格遵循 **Manifest V3** 标准；背景须为 `Service Worker`，禁止使用已废弃的 Background Pages。
  * AC2：浏览器 API 调用统一通过 `chrome.*` 命名空间（Edge 兼容），如需 Firefox 适配再引入 `webextension-polyfill`。
  * AC3：`manifest.json` 的 `icons`、`action.default_icon` 指向 `res/icons/`；`web_accessible_resources` 显式声明 `res/**` 与必要的 `src/**`，避免 CSP/CORS 阻断。
  * AC4：在 Chrome Web Store 与 Microsoft Edge Add-ons 上传打包时，均无 manifest 警告与权限过度声明。

### FR-008: P1 — 休息态（Idle/Rest）
* **需求描述：** 当鼠标长时间无移动（默认阈值 ≥ 8s 可配置），猫咪进入“休息态”（加载 `res/rest/sit_back/` 素材）；鼠标再次移动时平滑唤醒。
* **验收标准 (Acceptance Criteria):**
  * AC1：超时后自动进入休息态并停止高频姿态轮询，降低 CPU。
  * AC2：唤醒过渡平滑，无硬切。

### FR-009: P2 — 开关与置顶
* **需求描述：** 提供一键显隐（Popup 或快捷键）与“始终保持在视口内”的边界约束开关。
* **验收标准 (Acceptance Criteria):**
  * AC1：隐藏后完全移除注入层，释放事件监听；再次显示可恢复记忆位置。
  * AC2：边界约束开启时，拖拽不会把猫咪拖出可视区域。

## 4. 软件架构与工程规范 (Architectural Constraints & File Structure)

### 4.1 工程目录约定
```
cat_eyeing_mouse/
├── manifest.json                 # Manifest V3 清单（Chrome/Edge 兼容）
├── src/
│   ├── _locales/                 # ★ i18n 语言包（WebExtension 标准）
│   │   ├── en/messages.json
│   │   └── zh_CN/messages.json
│   ├── content/                  # Content Script：悬浮层 + Canvas 渲染 + 方向计算
│   ├── background/               # Service Worker：生命周期、存储、消息中转
│   └── popup/                    # Popup：开关、位置重置等
├── res/                          # ★ 所有静态资源集中目录
│   ├── move/                     # 8 方向 + 中心姿态帧 0~8.png
│   │   └── transitions/          # 过渡帧序列（生成产物）
│   ├── rest/sit_back/            # 休息态素材
│   └── icons/                    # 16/48/128 应用图标
└── tools/
    └── gen_transition_frames.js  # 基于 sharp 生成过渡帧的离线脚本
```

### 4.2 核心架构约束
* **隔离原则：** 悬浮层须注入于独立的高 `z-index` 容器（如 `Shadow DOM` 或独立 iframe），严禁污染宿主页面样式与 DOM；不得修改 `document.body` 已有节点的 `style`/`class`。
* **渲染管线：** Content Script 监听 `mousemove` → 计算 `atan2(dy, dx)` 归一化到 8 扇区 → 命中变化时驱动 Canvas 过渡（预生成帧序列播放 / crossfade）。
* **i18n 架构：** 所有 UI 文案经 `chrome.i18n.getMessage()` 取值；新增功能同步补齐 `zh_CN` 与 `en` 两份 messages.json。
* **资源加载：** 一律使用 `chrome.runtime.getURL('res/...')`；`web_accessible_resources` 以最小化原则开放 `res/**`。

### 4.3 跨浏览器打包规范
| 平台 | Manifest | 关键点 |
|------|----------|--------|
| Google Chrome Web Store | V3 | Service Worker；最小权限；`web_accessible_resources` 声明 `res/**` |
| Microsoft Edge Add-ons (Bing) | V3 | 复用 `chrome.*` API；图标三尺寸齐备；无外部网络请求 |

## 6. 边界情况与异常流 (Edge Cases & Exception Handling)

* **鼠标快速画圈/抖动：** 方向快速跳变时，过渡须合并/抢占，避免动画队列堆积；设置最小过渡间隔（如 60ms 节流）。
* **鼠标正好处于 45° 扇区边界：** 采用统一的“右开左闭”归类，杜绝同一坐标两次结果不一致。
* **素材加载失败/缺失：** 回退至上一有效帧或透明占位，记录 console.warn，不抛未捕获异常。
* **窗口缩放 / 视口越界：** 记忆坐标越界时回收到最近有效边缘；缩放过程中实时校正定位。
* **特殊页面（chrome://、商店页、PDF、about:blank）：** Content Script 无法注入时静默跳过，不报错。
* **多标签页 / 多窗口：** 每个标签页独立实例，互不干扰；位置存储按需共享或隔离（默认隔离）。
* **`visibilitychange` 隐藏：** 暂停 `requestAnimationFrame` 与事件轮询，切回时恢复。
* **高刷新率屏幕（120Hz/144Hz）：** 渲染循环跟随刷新率但姿态切换逻辑保持时间驱动，避免过度刷新。

## 7. 前提假设与系统依赖 (Assumptions & Dependencies)

### 7.1 前提假设
* 假设 `res/move/0.png`~`8.png` 的画面语义与本 PRD §FR-003 的方向映射一致（即美术资源按上述编号语义提供）。
* 假设 `res/rest/sit_back/sit_back.png` 为合法的休息态素材，可在静止超时后加载。
* 假设过渡帧可由 `gen_transition_frames.js`（基于 `sharp`）离线预生成并存入 `res/move/transitions/`，运行时直接序列播放。
* 假设用户浏览器版本满足 Manifest V3 最低要求。

### 7.2 系统依赖
* 运行时：Manifest V3（`chrome.storage.local`、`chrome.i18n`、`chrome.runtime.getURL`、Content Scripts、Service Worker）。
* 构建期（仅素材处理）：Node.js + `sharp`（已在 `package.json` 声明），用于离线生成过渡帧，不进入扩展运行时依赖。
* 前端技术：DOM + CSS + Canvas（`requestAnimationFrame`、`devicePixelRatio`），不引入重型运行时框架。

### 7.3 待确认事项（Open Questions）
* 是否需要 Firefox 适配（影响是否引入 `webextension-polyfill`）？— 默认仅 Chrome/Edge。
* 过渡策略最终选定“预生成帧序列”还是“运行时 crossfade”？— 默认预生成帧序列（性能更优），运行时 crossfade 作为备选。
* 休息态触发阈值是否需要用户可配置？— 默认固定 8s，是否暴露设置项待定。
